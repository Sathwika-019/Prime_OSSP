01 / Core concepts

One goal. Two communication channels.

Linux keeps each process in its own memory space. IPC provides a controlled path for exchanging information so programs can cooperate without directly accessing each other’s private memory.

⇄
Method 01

Unnamed pipe

A temporary communication channel typically used between related processes. The program creates a pipe, uses fork() to create a child, then sends data from one end and reads it from the other.

pipe()fork()read()write()close()
⌁
Method 02

FIFO · named pipe

A named communication channel represented by a special filesystem path. Separate programs can open the same FIFO and exchange a message without needing a parent–child relationship.

mkfifo()open()read()write()close()
02 / System architecture

03 / At a glance

Pipe vs FIFO

They both transfer data, but the way processes find and use the communication channel is different.

FeatureUnnamed pipeFIFO / named pipe
Creationpipe()mkfifo()
Channel identityFile descriptors managed by the processA named special file in the filesystem

LifetimeExists while open references remainThe FIFO pathname remains until removed

05 / Try it on Linux

Run the real C programs.

Open the project's CO3_Communication folder in your Linux/Ubuntu terminal. Use the commands below to compile and run the demonstrations from the supplied source package.

01 · Compile the pipe demo

gcc pipe_demo.c -o pipe_demo
./pipe_demo

Enter a message when prompted. The child process reads it from the pipe.

02 · Compile the FIFO demo

gcc fifo_demo.c -o fifo_demo
./fifo_demo reader
./fifo_demo writer

Run reader and writer in separate terminals. The reader waits until the writer sends a message.

Note: run the reader and writer commands in two separate terminals for the FIFO demonstration. The FIFO is created at /tmp/linux_os_management_fifo by the supplied C program.
